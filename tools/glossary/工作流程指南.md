# 公众号文章语料库处理工作流程指南

## 概述

本指南详细记录了处理公众号导出文章的标准工作流程，确保每次处理都遵循相同的规范和质量标准。

## 核心角色定义

**角色**: 专业翻译与文化顾问，专精于英式英语、汽车新闻（Jeremy Clarkson风格）和流行文化。

**任务**: 扫描提供的英文文本，提取高质量词汇表，指导简体中文（普通话）翻译。

## 输入格式

- 原始英文文本（来自书籍/文章）
- 中英双语对照文本

## 提取规则

### 1. 需要提取的内容

#### 汽车相关
- 具体车型、发动机部件、技术俚语（如"Lancia Beta"、"torque steer"、"flappy paddle gearbox"）

#### 文化锚点（关键）
- 英国品牌、政治家、名人（特别是90/00年代人物）、电视节目、地理位置（如"Marks and Spencer"、"Melton Mowbray"、"John Prescott"）

#### 克拉克森式表达
- 隐喻、夸张、特定口头禅（如"Power!"、"The baby Jesus"、特定侮辱性表达）

### 2. 需要忽略的内容
- 常见词汇（如"car"、"fast"、"road"），除非在特定习语中使用

## 输出字段定义

每个提取术语必须包含以下字段：

### source_term
- 英文术语的精确形式

### target_term
- **最佳简体中文翻译**
- **人名/地名**: 使用标准音译（如"Jeremy" -> "杰里米"）
- **昵称**: 翻译*含义*或*意图*（如"The G Dog" -> "杰哥"）

### category
- 从以下选项中选择：["Automotive"、"Named Entities"、"Idioms/Metaphors"]

### description
- 术语背景的简要说明
- 这个人物是谁？这辆车以什么闻名？为什么这个表达有趣？

### instruction
- 给翻译者的具体建议
- 应该音译吗？需要脚注吗？语气应该是嘲讽的吗？

## 输出格式

提供原始JSON对象列表，不使用Markdown代码块。

```json
[
  {
    "source_term": "Melton Mowbray",
    "target_term": "梅尔顿莫布雷",
    "category": "Named Entities",
    "description": "A town in Leicestershire, England, famous for its pork pies. Used here as a benchmark for authenticity.",
    "instruction": "Transliterate. Consider adding a footnote if the context implies 'the home of pies'."
  },
  {
    "source_term": "flappy paddle",
    "target_term": "换挡拨片",
    "category": "Automotive",
    "description": "Refers to the paddle shifters on the steering wheel.",
    "instruction": "Use the standard automotive term, but keep the casual tone if possible."
  }
]
```

## 工作流程

### 第一步：准备工作
1. 检查`history.txt`文件是否存在
2. 如果不存在则创建空文件
3. 扫描"公众号导出"文件夹中的文件列表

### 第二步：处理单个文件
1. **读取文件**: 完整读取文章内容
2. **分析内容**: 
   - 识别汽车相关术语
   - 提取文化锚点
   - 标记克拉克森式表达
3. **生成JSON**: 按照标准格式创建词汇表
4. **保存文件**: 保存为同名`.json`文件
5. **记录历史**: 在`history.txt`中记录处理过的文件名

### 第三步：质量控制
1. **术语一致性**: 确保相同术语在不同文章中的翻译一致
2. **文化准确性**: 验证文化背景描述的准确性
3. **格式检查**: 确保JSON格式正确无误

### 第四步：批量处理
1. 按顺序处理所有文件
2. 避免重复处理已记录的文件
3. 维护处理进度的透明度

## 文件命名规范

### 输入文件
- 位于`公众号导出/`文件夹
- 扩展名：`.md`
- 命名示例：`2024克拉克森团队年度车评_这一年_我们最喜欢哪些车_.md`

### 输出文件
- 与输入文件同名
- 扩展名：`.json`
- 保存位置：与输入文件相同目录
- 命名示例：`2024克拉克森团队年度车评_这一年_我们最喜欢哪些车_.json`

## 历史记录管理

### history.txt格式
- 每行一个已处理文件名
- 按处理时间顺序排列
- 用于避免重复处理

```
2023年12月我自己的工作间_入组测试结果及分析.md
2023年3月我自己的工作间_入组测试结果及分析.md
2024克拉克森团队年度车评_这一年_我们最喜欢哪些车_.md
```

## 特殊处理规则

### 汽车品牌处理
- **品牌名**: 使用中文标准译名（如"Porsche" -> "保时捷"）
- **车型名**: 保持英文或标准译名（如"Macan" -> "Macan"）
- **组合**: 品牌名+车型名（如"Porsche Macan" -> "保时捷Macan"）

### 人名处理
- **英文名**: 使用标准音译（如"Jeremy Clarkson" -> "杰里米·克拉克森"）
- **中文名**: 保持原样（如"詹姆斯·梅" -> "詹姆斯·梅"）

### 地名处理
- **英国地名**: 使用标准音译（如"Land's End" -> "兰兹角"）
- **知名地标**: 使用公认译名（如"Westminster Abbey" -> "威斯敏斯特教堂"）

## 错误处理

### 文件不存在
- 跳过并记录错误
- 继续处理下一个文件

### JSON格式错误
- 验证JSON格式正确性
- 重新生成格式正确的文件

### 重复处理
- 检查`history.txt`避免重复
- 如果已处理，跳过该文件

## 质量保证检查清单

- [ ] 所有术语都正确分类
- [ ] 描述信息准确且有用
- [ ] 翻译建议具体可行
- [ ] JSON格式正确
- [ ] 文件名记录完整
- [ ] 术语翻译一致性检查
