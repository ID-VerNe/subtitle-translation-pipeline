# 字幕翻译流水线 (Subtitle Translation Pipeline)

本模块是整个项目的核心翻译引擎，旨在通过 **"全局画像扫描"** 与 **"分治式两阶段翻译"** 架构，解决传统字幕翻译中上下文断裂、角色代词混乱、专有名词不统一等顽疾。

---

## 核心架构原理 (Architecture Principles)

整个 Pipeline 遵循以下六个关键步骤，实现了从"纯文本翻译"到"剧本感知式翻译"的跨越。

### 1. 全局画像扫描 (Global Discovery)

-   **痛点**：LLM 每次只能看到几十行字幕，不知道整部片的题材和人物背景。
-   **解法**：在正式翻译前，系统对全文进行 **15% 三段式均衡采样**（首、中、尾各 15%，覆盖影片的开场、发展、结尾），利用 LLM 生成一份包含：**影片类型 (Genre)、整体语调 (Tone)、详细人物画像 (Characters, 含性别/说话风格)、人物关系图谱 (Relationships)** 的全局报告。
-   **特点**：采样比例和位置是固定的，以保证稳定性和可复现性。
-   **产出**：`global_profile.json`。

### 2. 场景映射与对齐 (Scene Mapping)

-   **痛点**：批次 (Batch) 切分往往是死板的，会切断对话。
-   **解法**：系统先将全文按固定粒度切分为基础场景块，再由 LLM 对每个场景进行语义富化——识别**参与者列表、场景摘要、特定语域 (Domain)**。场景边界是固定的，但场景的内容理解是语义化的。
-   **结果**：翻译批次对齐到这些固定边界上，保证同一批字幕落在同一个语境里。
-   **产出**：`scene_map.json`。

### 3. 三级智能术语库 (Intelligent Glossary)

-   **核心库 (Core)**：存放全片最核心的专有名词，全程跟随。
-   **动态库 (Local)**：每批次翻译前，根据当前文本内容（通过子串匹配）过滤出相关的术语。
-   **人名库 (Name DB)**：集成 67 万条《世界人名翻译大辞典》数据。通过 **LLM NER (命名实体识别)** 提取文中人名，并在库中自动匹配，彻底解决 `Will` (动词 vs 人名) 等歧义。

### 4. 两阶段执行引擎 (Two-Stage Engine)

-   **阶段 A：直译 (Literal Stage)**：专注于 **ID 对应** 与 **语义还原**。通过 Tool Calling (Function Calling) 强制模型输出 JSON，并进行严格的格式校验。
-   **阶段 B：润色 (Polish Stage)**：基于直译结果，注入 **全局画像**、**翻译策略** 和 **场景引导**。
-   **后置防御层**：润色完成后，系统会自动清理 LLM 擅自添加的括号注释（原文没有括号时尤其如此）。这是在提示词约束之外的第二道防线，专门兜底模型过度解释的倾向。
-   **性能优化**：引入 **异步预取 (Prefetch)**。当 Pipeline 在润色批次 `i` 时，后台已在并发进行批次 `i+1` 的直译。

### 5. 梯次拯救引擎 (Ladder Rescue Engine)

-   **痛点**：长文本翻译经常遇到 API 超时或内容安全拦截 (Content Filter)。
-   **解法**：遇到失败时，系统自动启动 **三级降级策略**：
    1.  **TIER 1 (Full)**：减小批次大小重试（如 8->4->2->1）。
    2.  **TIER 2 (Compact)**：剥离最近的动态记忆，保留场景引导重试。
    3.  **TIER 3 (Minimal)**：剥离场景引导，仅保留全局画像与核心术语重试。
-   **拒绝感知**：系统会记住模型拒绝过的行，在后续降级和缩批次时主动跳过它们，避免反复用已失败的内容撞墙。
-   **兜底**：若全部失败，直译阶段退回原文，润色阶段退回直译结果，确保任务永不中断。这是显式的取舍：**完整性优先于质量**。

### 6. 质量增强层 (Optional Quality Layers)

以下模块构成了流水线的可选能力层，用于进一步提升翻译质量与场景适应性。

#### 6a. Few-Shot 示例引导 (Few-Shot Guidance)

-   **概念**：针对不同场景类型（幽默、技术、情感强烈等），预置少量高质量翻译示例作为参考，引导模型在润色阶段模仿特定风格。示例随场景特征自动匹配，而非通用地塞入所有请求。

#### 6b. 翻译质量检查器 (Quality Checker)

-   **概念**：在翻译完成后，用一组规则对译文做独立的质量检查，包括：书面语过重、机翻痕迹、长度异常、情感标记丢失，以及术语一致性回查。这是独立于 LLM 的、基于硬规则的第二道质检。

#### 6c. 动态温度策略 (Dynamic Temperature Strategy)

-   **概念**：不同场景需要不同的翻译温度——技术性内容用低温度以求精确，幽默/情感内容用高温度以求创造力。系统根据场景特征（语域、是否含数字/俚语等）自动调整直译和润色阶段的温度值，而非使用全局固定值。

## 关键技术实现

### 智能负载均衡 (Smart Load Balancer)

-   支持 **多 API Key 自动调度**，实时监控每组 API 的成功率、响应时间和可用槽位。
-   针对特定模型（如 `GLM-4-Flash`）内置并发优化策略，自动压制并发以防止 429 报错。
-   使用 `json_repair` 与多层正则提取技术，确保在模型输出非规范 JSON 时仍能稳健解析。

### 动态上下文压缩

-   为了防止 Context 膨胀导致 Token 浪费和理解力下降，Pipeline 会根据当前场景参与者，**动态压缩** 全局画像中的角色信息，仅回灌相关的角色背景。

## 模块文件结构

```text
subtitle/
├── translate_srt_llm.py    # 核心翻译流水线 CLI 入口
├── gui_app.py              # 图形界面入口 (MVC 架构)
├── main.py                 # 一键提取与翻译的统一入口
├── core/                   # 核心翻译逻辑
│   ├── memory/             # 记忆引擎 (全局画像、策略、场景对齐)
│   ├── stages/             # 翻译阶段 (直译、润色)
│   ├── context_builder.py  # 动态前情提要构建
│   ├── rescue_engine.py    # 梯次拯救引擎 (重试逻辑)
│   └── terminology_extractor.py # NER 术语提取
├── pipeline/               # 任务编排与调度
│   ├── orchestrator.py     # 核心调度器 (异步流水线与并发控制)
│   ├── checkpoint_manager.py # 断点续传与进度管理
│   └── srt_writer.py       # 字幕文件生成
├── network/                # 网络与请求层
│   ├── llm_client.py       # 大模型客户端与 JSON 解析
│   └── request_handler.py  # 智能负载均衡与速率限制 (Smart Load Balancer)
├── gui/                    # GUI 视图与控制器
│   ├── main_window.py      # Tkinter 纯视图布局
│   ├── view_models.py      # 状态管理
│   ├── preset_manager.py   # 环境预设管理
│   └── task_controller.py  # 异步任务驱动器
├── media/                  # 媒体处理
│   └── extractor.py        # MKV 提取与 ASS 转换桥接
├── pre-process/            # 前置字幕提取脚本
└── post-process/           # 后置特效生成脚本
```
